# Android TV Time Fixer

**Исправление проблем с синхронизацией времени на Android TV**

## Описание проблемы

Многие телевизоры и Android TV-приставки, особенно в регионах с сетевыми ограничениями, сталкиваются с проблемой сброса системных часов после отключения от электросети. Несмотря на включенную функцию автоматической синхронизации времени, устройство не может подключиться к серверу времени, что приводит к следующим последствиям:

*   **Потеря доступа к интернет-приложениям:** Многие приложения требуют точного времени для корректной работы.
*   **Необходимость ручной установки времени:** Пользователю приходится вручную выставлять время каждый раз после отключения устройства от питания.
*   **Сообщение "Подключено, без доступа к интернету" в настройках Wi-Fi:** Это индикатор того, что устройство не может синхронизировать время с сервером.

**Причина:** Основной причиной является невозможность подключения устройства к стандартному NTP-серверу Google (`time.android.com`) из-за сетевых ограничений в указанных регионах.

**Решение:** Android TV Time Fixer позволяет решить эту проблему, заменяя стандартный NTP-сервер Google на альтернативный, доступный в вашем регионе.

## О программе

**Android TV Time Fixer** — это кроссплатформенная утилита для Windows, Linux и macOS, предназначенная для управления настройками NTP-сервера на устройствах Android TV через ADB (Android Debug Bridge).

Начиная с версии 2.6.0 у проекта две половины:

*   **Программа для компьютера** — полнофункциональная консольная утилита,
    описанная ниже. Windows, Linux, macOS.
*   **Приложение для Android (APK, экспериментальное)** — то же самое с
    телефона или планшета, без компьютера вообще. См. раздел
    [Приложение для Android](#приложение-для-android).

    *   Отображение времени отклика (RTT)
    *   Процент успешных подключений
    *   Сортировка по доступности и скорости
    *   Экспорт/импорт настроек в JSON

    *   Спаривание с устройством по 6-значному коду прямо из программы
    *   Поиск устройств по mDNS — не нужно знать ни IP, ни порт
    *   Автоматическое определение протокола: программа сама понимает, работает

    *   **Linux и macOS:** ADB-ключи и список спаренных устройств хранятся
        рядом с программой, так что она не трогает ваш `~/.android`
        (на Windows `adb` определяет профиль через системный API и такую

*   **Сканирование сети и групповые операции:**
    *   Автоматическое сканирование локальной сети на устройства Android TV
    *   Настраиваемый ADB-порт сканирования (по умолчанию 5555)
    *   Подключение к найденным устройствам
    *   Групповое обновление NTP-сервера на нескольких устройствах

*   **Режим терминала:**
    *   Выполнение любых ADB-команд
    *   Выполнение системных команд
    *   Встроенная справка по командам ADB

*   **Приложение для Android (новое, экспериментальное):**
    *   Отдельный APK: смена NTP-сервера прямо с телефона, компьютер не нужен

    *   Сведения об устройстве: модель, Android, память, экран, uptime и прочее
    *   Интерфейс на русском и английском по языку системы

## Установка

### Windows

1.  Скачайте архив `AndroidTVTimeFixer-windows.zip` из раздела [Releases](https://github.com/civisrom/android-tv-date-time/releases).
2.  Распакуйте архив в удобное место на вашем компьютере, например, `D:\AndroidTVTimeFixer`.
3.  Запустите `AndroidTVTimeFixer.exe` или используйте `start.bat` / `start.ps1`.

Запуск через **PowerShell**

1.  Откройте **PowerShell** от имени администратора.
2.  Перейдите в папку с программой:
    ```powershell
    cd "D:\AndroidTVTimeFixer"
    ```
3.  Запустите программу:
    ```powershell
    .\AndroidTVTimeFixer.exe
    ```

### Linux

1.  Скачайте архив `AndroidTVTimeFixer-linux.zip` из раздела [Releases](https://github.com/civisrom/android-tv-date-time/releases).
2.  Распакуйте архив:
    ```bash
    unzip AndroidTVTimeFixer-linux.zip
    ```
3.  Сделайте файл исполняемым и запустите:
    ```bash
    chmod +x AndroidTVTimeFixer
    ./AndroidTVTimeFixer
    ```

### macOS

1.  Скачайте архив `AndroidTVTimeFixer-macos.zip` из раздела [Releases](https://github.com/civisrom/android-tv-date-time/releases).
2.  Распакуйте архив и запустите приложение.

### Android (APK)

1.  Скачайте `AndroidTVTimeFixer-2.6.1.apk` из раздела [Releases](https://github.com/civisrom/android-tv-date-time/releases).
2.  Сверьте контрольную сумму с файлом `.apk.sha256` рядом:
    ```bash
    sha256sum -c AndroidTVTimeFixer-2.6.1.apk.sha256
    ```
3.  Установите:
    *   **На телефон** — откройте файл и разрешите установку из неизвестных
        источников для файлового менеджера или браузера.
    *   **На сам Android TV** — либо через `adb install AndroidTVTimeFixer-2.6.1.apk`
        с компьютера, либо любым файловым менеджером на телевизоре. Иконка
        появится и в обычном лаунчере, и в лаунчере Android TV.

Требуется **Android 6.0** или новее. Подробности — в разделе
[Приложение для Android](#приложение-для-android).

**Про предупреждение Google Play Защиты.** При установке APK не из Google Play
система показывает «Приложение заблокировано для защиты устройства» с пояснением,
что Play Защита никогда не проверяла приложения этого разработчика. Это
ожидаемое поведение для **любого** стороннего APK, а не признак проблемы:
приложение не публикуется в Google Play. Нажмите «Все равно установить».
Подлинность файла проверяется контрольной суммой из шага 2 и подписью APK.

### Данные приложения

Программа переносимая: ADB-ключи, настройки и журнал хранятся **рядом с исполняемым файлом**
(`keys/`, `adb/`, `settings.json`, `saved_servers.json`, `android_tv_fixer.log`).

- `keys/` — ключ для прямого подключения по «отладке по сети» (старый протокол ADB).
- `adb/` — собственный каталог `adb` для беспроводной отладки Android 11+: там
  лежат ключ и список спаренных устройств. При первом запуске существующие ключи
  из `~/.android` копируются сюда, чтобы уже спаренные устройства продолжили
  работать. **Только Linux и macOS:** на Windows `adb` определяет профиль
  пользователя через системный API и игнорирует переменные окружения, поэтому
  его ключи там остаются в `%USERPROFILE%\.android` (проверено на
  platform-tools 37.0.1).

Собственный порт ADB-сервера программа использует на **всех** платформах,
поэтому она не мешает вашему `adb` и Android Studio и не завершает их сессии.

Если в папку программы писать нельзя (например, установка в `Program Files` или запуск
прямо из архива), данные автоматически уходят в каталог пользователя:

- Windows: `%LOCALAPPDATA%\AndroidTVTimeFixer`
- Linux: `$XDG_DATA_HOME/AndroidTVTimeFixer` или `~/.local/share/AndroidTVTimeFixer`
- macOS: `~/Library/Application Support/AndroidTVTimeFixer`

В этом случае при первом запуске существующие настройки и ADB-ключи из папки программы
копируются автоматически.

## Подготовка Android TV

### Шаг 1. Включите режим разработчика

1.  Откройте на вашем Android TV: **Настройки** > **Настройки устройства** > **Об устройстве**.
2.  Нажмите 7 раз на пункт **"Сборка"**, чтобы разблокировать режим разработчика.
3.  Перейдите: **Настройки устройства** > **Для разработчиков**.

### Шаг 2. Включите отладку — один из двух вариантов

В разделе «Для разработчиков» найдите **один** из этих пунктов. Какой именно
доступен — зависит от прошивки, а не от версии Android.

**Вариант А — «Отладка по сети» (классический).** Есть на большинстве
телевизоров и приставок: Xiaomi, TCL, Nvidia Shield, Fire TV. Просто включите
переключатель. Устройство начнёт слушать порт **5555**, и программе достаточно
его IP-адреса.

**Вариант Б — «Беспроводная отладка» (Android 11+).** Единственный вариант на
Google TV Streamer и Chromecast with Google TV после обновления до Android 14.
Включите переключатель и **оставьте экран открытым** — порты на нём случайные и
меняются. Дальше работайте через **пункт 11** главного меню (см. раздел
«Беспроводная отладка» ниже).

> Программа определяет вариант сама: достаточно ввести адрес, и она скажет,
> нужен ли код спаривания.

### Шаг 3. Разрешите автосинхронизацию времени

1.  Откройте: **Настройки** > **Дата и время**.
2.  Включите: **Автонастройка даты и времени** > **Использовать время сети**.

Без этого устройство не станет обращаться к NTP-серверу, который вы зададите.

### Шаг 4. После настройки

Для повышения безопасности рекомендуется отключить режим разработчика после
завершения настройки NTP-сервера. Заданный NTP-сервер сохраняется в системе и
переживает перезагрузку — отладка нужна только на время настройки.

## Новая беспроводная отладка на современных Android TV

Этот раздел объясняет, зачем новые версии обеих программ поддерживают не только
старый ADB по сети, но и современную **Wireless debugging** со спариванием.

Важно различать версию протокола и версию конкретного телевизора. Современная
Wireless debugging появилась в Android 11 для телефонов; официальная поддержка
TV начинается с Android 13. На устройствах с Android TV / Google TV 14 она
особенно важна, потому что в некоторых прошивках это единственный доступный
сетевой режим ADB. То есть Android 14 не создал новый несовместимый протокол,
но именно после обновления до Android 14 многие пользователи впервые столкнулись
с ним вместо привычной «Отладки по сети».

### В чём проблема

На некоторых актуальных Google TV, включая **Google TV Streamer** и обновлённые
**Chromecast with Google TV**, в параметрах разработчика вместо старой
**«Отладки по сети»** доступен экран **«Беспроводная отладка»** со спариванием
по коду.

Из-за этого перестают работать все старые инструкции, которых полно в интернете:
`adb tcpip 5555`, подключение на порт 5555, «включите отладку по сети и
подключитесь по IP». Человек доходит до момента «включите отладку по сети»,
не находит такого пункта — и упирается в тупик. Именно ради этого случая обе
программы и обновлялись.

### Чем новая схема отличается от старой

| | Старая «Отладка по сети» | Современная Wireless debugging |
|---|---|---|
| Первый доступ | подтверждение RSA-ключа или уже разрешённый клиент | обязательное спаривание по 6-значному коду |
| Порт | обычно постоянный `5555` | динамические и разные pairing/connect-порты |
| Обнаружение | IP и порт часто вводятся вручную | сервисы объявляются в локальной сети через mDNS |
| Транспорт | обычный ADB TCP | аутентифицированное TLS-подключение после pairing |
| Повторное использование | сохранённый адрес часто работает снова | доверенный ключ сохраняется, но актуальный порт может измениться |

Из этого следуют три важных правила:

*   **Нужно спаривание.** Устройство не примет новый клиент, пока вы не введёте
    6-значный код из текущего открытого окна. После успешного pairing ключ
    остаётся доверенным до отзыва авторизации, очистки данных или переустановки.
*   **Порты случайные.** Для спаривания и для подключения они **разные**, и оба
    меняются при каждом включении беспроводной отладки. Записать их один раз и
    пользоваться дальше нельзя.
*   **Соединение шифрованное.** Старые клиенты ADB его просто не понимают.

Поэтому mDNS здесь решает реальную проблему: программа получает актуальные
адреса pairing и connect из объявлений самого устройства и не заставляет
пользователя переписывать меняющиеся порты. Если роутер блокирует multicast,
оба адреса по-прежнему можно ввести вручную.

Официальное описание требований и процедуры pairing находится в
[документации Android Debug Bridge](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi).

### Что даёт новая версия программы для компьютера

Desktop-версия для **Windows, Linux и macOS** полноценно поддерживает современную
Wireless debugging. Это не функция только Android-приложения: компьютерная
сборка умеет сама найти новый ADB-сервис, выполнить pairing по коду и затем
подключиться к защищённому connect-порту. Отдельно устанавливать Android Studio,
SDK Platform Tools или системный `adb` не требуется.

*   **Одинаковый сценарий на трёх ОС.** В Windows, Linux и macOS доступны
    обнаружение, pairing, повторное подключение и все операции с NTP. Отличается
    только способ изоляции файлов ADB: на Linux и macOS они хранятся рядом с
    программой, а на Windows расположение профиля определяет сам `adb`.
*   **Спаривание по коду прямо из программы.** Пользователь открывает на TV
    «Подключение с помощью кода», выбирает найденное устройство или вводит адрес
    pairing вручную, затем вводит шесть цифр. Встроенный `adb` выполняет pairing
    и сохраняет доверенную идентичность для последующих соединений.
*   **Раздельное обнаружение по mDNS.** Программа распознаёт сервис ожидания
    спаривания и сервис готового TLS-подключения как разные назначения. Поэтому
    pairing-порт не используется ошибочно вместо connect-порта.
*   **Актуальный динамический порт во всём интерфейсе.** Во всех пунктах меню,
    где нужен адрес, программа ищет TV и предлагает выбрать его номером. Это
    особенно полезно после перезапуска Wireless debugging, когда порт изменился.
    Если mDNS заблокирован роутером, адрес остаётся доступен для ручного ввода.
*   **Автоопределение старого и нового ADB.** Классическая «Отладка по сети» на
    порту 5555 продолжает работать. Для современной Wireless debugging программа
    использует pairing и защищённое TLS-соединение; пользователь не выбирает
    внутренний транспорт вручную.
*   **Проверка соединения, а не доверие сообщению `adb connect`.** Программа
    выполняет короткую shell-пробу и не показывает «Подключено», если устройство
    рекламирует порт, но ещё не доверяет ключу.
*   **Собственный ADB-сервер.** Программа не мешает вашему `adb` и не завершает
    сессии Android Studio.
*   **Все функции после Wireless pairing.** Защищённое соединение используется
    так же, как старое: доступны выбор и проверка NTP, чтение текущего значения,
    сведения об устройстве, групповые операции и терминал. Pairing является
    способом получить доступ, а не отдельным ограниченным режимом программы.

Итог для пользователя: даже если после обновления TV до Android 14 в настройках
больше нет старой «Отладки по сети», desktop-программа не теряет возможность
управлять NTP. Она закрывает весь путь от шестизначного кода и меняющихся портов
до проверенного подключения и применения настройки.

Подробная пошаговая инструкция — в разделе
[Пункт 11 — Беспроводная отладка Android 11+](#пункт-11--беспроводная-отладка-android-11).

### Что даёт приложение для Android

То же самое, **но без компьютера вообще**. После отключения питания на TV могут
сбиться часы, из-за чего HTTPS и интернет-приложения перестают работать. С APK
достаточно взять телефон в той же Wi-Fi-сети: не нужен USB-кабель, Android SDK,
командная строка или ручная установка `adb`.

Это не просто удалённая командная строка. Приложение ведёт пользователя по
готовому безопасному сценарию и само выполняет технические шаги:

*   находит отдельно сервис ожидания pairing и сервис готового подключения;
*   принимает одноразовый 6-значный код и создаёт постоянную ADB-идентичность;
*   устанавливает защищённое соединение и подтверждает его реальной командой;
*   показывает понятную причину отказа вместо необработанного вывода shell;
*   проверяет выбранный сервер настоящим SNTP-запросом до изменения настройки;
*   применяет NTP и перечитывает значение с TV, подтверждая результат;
*   умеет работать и со старой «Отладкой по сети» без pairing.

APK можно запустить на телефоне/планшете как пульт настройки или установить на
сам Android TV. Во втором случае приложение может подключиться к адресу этого
же телевизора, поэтому для исправления NTP не требуется второе устройство.
Подробно — в разделе
[Приложение для Android](#приложение-для-android).

## Как пользоваться программой

### Пункт 1 — Изменить сервер времени NTP по коду страны

Программа запрашивает адрес вашего устройства (телевизора или приставки) — можно ввести просто `192.168.1.20`, либо `192.168.1.20:37105`, если порт нестандартный, либо `s` для поиска в сети. Затем она подключается по ADB, показывает текущие настройки и предлагает ввести двухбуквенный код страны (например, `ru`, `by`, `de`). Можно ввести `?название` для поиска страны по названию. После выбора кода программа автоматически установит NTP-сервер соответствующего региона.

> **Подсказка:** Если вы не знаете код своей страны, сначала откройте **пункт 3** — там отображается полный список кодов стран с названиями и NTP-серверами. Скопируйте нужный код в буфер обмена и вставьте его при запросе в пункте 1.

### Пункт 2 — Изменить сервер времени NTP на пользовательский

Аналогично пункту 1, но вместо кода страны вы вводите адрес NTP-сервера вручную (доменное имя или IP-адрес). Программа проверит корректность формата и установит указанный сервер на устройство.

> **Подсказка:** Адрес NTP-сервера можно взять из **пункта 3** (серверы по странам) или **пункта 4** (альтернативные серверы — Cloudflare, Google и др.). Откройте нужный пункт, скопируйте адрес сервера в буфер обмена и вставьте его при запросе в пункте 2.

### Пункт 3 — Показать коды стран с названиями и NTP-серверами

Выводит полный список поддерживаемых кодов стран (65+), их названия и соответствующие NTP-серверы. Можно использовать интерактивный поиск. Результаты можно скопировать в буфер обмена.

> **Использование результатов:** Скопированный код страны можно вставить в **пункте 1**, а скопированный адрес NTP-сервера — в **пункте 2** при ручной настройке.

### Пункт 4 — Показать доступные альтернативные NTP-серверы

Показывает список альтернативных NTP-серверов: региональные пулы, Cloudflare, Google и другие. Результаты можно скопировать в буфер обмена.

> **Использование результатов:** Скопированный адрес сервера можно вставить в **пункте 2** для ручной установки на устройство.

### Пункт 5 — Показать текущую информацию об устройстве

Подключается к устройству и выводит подробную информацию: модель, производитель, версия Android, серийный номер, CPU, RAM, разрешение экрана, сетевые параметры (IP, MAC), текущий NTP-сервер, часовой пояс, аптайм, а также сравнение времени устройства и ПК.

### Пункт 6 — Пинговать NTP-серверы

Проверяет доступность всех известных NTP-серверов (110+). Показывает время отклика (RTT), процент успешных подключений, сортирует результаты по доступности и скорости.

### Пункт 7 — Управление серверами

Открывает подменю для работы с избранными серверами:
- **Показать избранные** — список сохранённых серверов
- **Добавить текущий сервер** — сохраняет текущий NTP-сервер устройства в избранное
- **Копировать сервер** — копирует текущий сервер устройства в буфер обмена
- **Вставить сервер** — устанавливает на устройство сервер из буфера обмена
- **Удалить сервер** — удаляет выбранный сервер из списка избранного
- **Экспорт / Импорт настроек** — сохранение и восстановление всех настроек (язык, IP, избранные серверы) в JSON-файл

### Пункт 8 — Сканирование сети и групповое обновление NTP

Открывает подменю для работы с несколькими устройствами:
- **Сканировать сеть** — сначала спрашивает ADB-порт (Enter — 5555, значение запоминается), затем находит устройства Android TV в локальной сети. Найденные адреса показываются в виде `IP:порт`, так что нестандартный порт дальше подставляется сам
- **Подключиться к найденному устройству** — выбрать и подключиться к одному из обнаруженных устройств
- **Групповое обновление NTP** — установить NTP-сервер сразу на все найденные или вручную введённые устройства
- **Статус синхронизации времени** — сравнить время устройства с временем ПК

### Пункт 9 — Автоматическая установка NTP-сервера (экспериментальный режим)

Полностью автоматический режим:
1. Спрашивает ADB-порт и сканирует локальную сеть, находя устройства Android TV
2. Подключается к выбранному устройству
3. Определяет ваш регион по часовому поясу системы
4. Проверяет все доступные NTP-серверы (110+) и измеряет скорость отклика
5. Показывает Топ-5 самых быстрых серверов с RTT, процентом успешности и смещением
6. Автоматически рекомендует лучший сервер
7. Устанавливает выбранный сервер на устройство

### Пункт 10 — Режим терминала

Интерактивный режим для выполнения любых ADB и системных команд. Полезен для продвинутых пользователей:
- Управление приложениями (установка, удаление)
- Передача файлов (push/pull)
- Снимки экрана и запись видео
- Диагностика системы
- Перезагрузка устройства

Команды: `help` — справка, `clear` — очистка экрана, `exit` — выход из терминала.

### Пункт 11 — Беспроводная отладка Android 11+

Этот пункт нужен, если на устройстве в разделе «Для разработчиков» есть
**«Беспроводная отладка»** вместо «Отладки по сети» — так устроены Google TV
Streamer и Chromecast with Google TV на Android 14.

Открывает подменю из двух действий.

**1. Спарить устройство по коду.** Однократная процедура: после неё компьютер
и телевизор знают друг друга, и повторять её не нужно.

1.  На телевизоре: **Для разработчиков** > **Беспроводная отладка** >
    **Подключение с помощью кода**. На экране появятся адрес, порт и
    6-значный код.
2.  В программе выберите пункт 1. Она сама поищет устройства по mDNS и покажет
    список — выберите номером. Если mDNS недоступен, введите адрес вручную в
    виде `192.168.1.20:41234` (порт **спаривания** с экрана телевизора).
3.  Введите 6-значный код.
4.  После успешного спаривания программа спросит адрес для подключения.
    **Внимание: это другой порт.** Он показан на основном экране «Беспроводная
    отладка», а не в окне спаривания. Через mDNS программа подставит его сама.

**2. Найти устройства по mDNS.** Показывает две группы: устройства, ожидающие
спаривания (у них на экране открыт диалог с кодом), и готовые к подключению.
Из второй группы можно сразу подключиться, выбрав номер. Во вторую группу
попадают и устройства с классической «Отладкой по сети» — на части прошивок
(например, Nvidia Shield) экрана «Беспроводная отладка» нет вовсе, и устройство
объявляет себя только старым способом.

**Поиск по mDNS работает и во всех остальных пунктах меню.** Везде, где
программа спрашивает адрес устройства, она сначала сама ищет его в сети и
показывает найденное нумерованным списком — достаточно ввести номер. Порт при
этом подставляется правильный, даже если беспроводная отладка сменила его при
последнем включении. Остальные способы никуда не делись:

| Ввод | Что произойдёт |
|---|---|
| номер из списка | подключиться к найденному устройству |
| Enter | взять сохранённый адрес |
| `192.168.1.20` или `192.168.1.20:37105` | ввести адрес вручную |
| `m` | искать по сети заново (порт мог смениться) |
| `s` | просканировать всю подсеть перебором |
| `192.168.1.0/24` | просканировать указанную подсеть |
| `q` | вернуться в меню |

> **Почему без mDNS неудобно.** Беспроводная отладка выдаёт **случайные** порты,
> причём для спаривания и для подключения — разные, и они меняются при каждом
> включении. Обнаружение по mDNS избавляет от их переписывания с экрана.
> Программа сначала пробует встроенный `adb`, а если у него нет mDNS-бэкенда —
> библиотеку `zeroconf`. Если не работает ни то, ни другое, останется ручной
> ввод адреса.

После спаривания и подключения все остальные пункты меню работают как обычно:
смена NTP, информация об устройстве, терминал.

Завершение работы программы.

## Приложение для Android

Отдельный APK превращает телефон, планшет или сам телевизор в специализированный
инструмент настройки NTP через ADB. Он поддерживает как классический порт 5555,
так и современную Wireless debugging со спариванием, динамическими портами,
mDNS-обнаружением и защищённым подключением. Пользователь получает готовые
кнопки и проверку результата вместо необходимости знать команды ADB.

Основной сценарий: приложение обнаруживает TV, помогает один раз спарить его по
коду, подключается по актуальному connect-порту, проверяет доступность выбранного
сервера времени, применяет настройку и читает её обратно с устройства. Всё это
можно сделать с телефона или прямо на TV, без компьютера.

### Что нужно приготовить до начала

1. **Телефон и телевизор должны быть в одной сети Wi-Fi.** Не «домашняя» и
   «гостевая», а именно одна — иначе они друг друга не увидят.
2. **На телевизоре включён режим разработчика** и отладка. Как это сделать —
   в разделе [Подготовка Android TV](#подготовка-android-tv) выше, он общий для
   обеих программ.
3. Мобильный интернет на телефоне лучше выключить: иначе часть запросов может
   уйти в сотовую сеть мимо Wi-Fi.

### Экран приложения сверху вниз

Приложение — один экран, который листается. Разделы идут в том порядке, в
каком ими пользуются.

#### 1. Заголовок и режим работы

Под названием одна строка: «Запущено на телефоне: подключение к телевизору по
сети» либо «Запущено на телевизоре». Приложение определяет это само, менять
ничего не нужно.

#### 2. «Подключение к устройству»

Здесь показано текущее состояние, и **оно выделено цветом**, чтобы было видно
сразу, не вчитываясь:

*   **зелёным** — «Подключено к 192.168.0.112:5555», связь есть;
*   **красным** — «Не подключено» либо причина отказа;
*   обычным цветом — «Подключение к…», пока идёт попытка.

**Поле ввода** принимает две записи:

| Что вводить | Когда |
|---|---|
| `192.168.0.112` | обычно; порт `5555` подставится сам |
| `192.168.0.112:37105` | если у отладки нестандартный порт |

Адрес телевизора смотрят в его настройках: **Настройки → Сеть и Интернет →**
ваша сеть, либо **Настройки → Об устройстве → Состояние**.

Кнопка **«Подключиться»** проверяет связь по-настоящему: она выполняет на
телевизоре пробную команду и смотрит на ответ. Поэтому «Подключено» здесь
означает, что связь действительно есть, а не что адрес похож на правильный.

**Что может ответить кнопка:**

*   *«Подтвердите запрос на экране устройства»* — на телевизоре появилось окно
    «Разрешить отладку с этого компьютера?». Нажмите там **«Разрешить»** (и
    лучше отметьте «Всегда разрешать»), затем повторите подключение.
*   *«Устройству нужно спаривание по коду»* — это Android 11+ с беспроводной
    отладкой, см. раздел «Спаривание» ниже.
*   *«Не удаётся достучаться до устройства»* — телевизор не отвечает по этому
    адресу: другая сеть, опечатка в адресе, либо отладка выключена.
*   *«Неверный адрес»* — в поле не IP-адрес.

Когда связь установлена, поле ввода сменяется кнопкой **«Отключиться»**.

#### 3. «Автоматически обнаруженные устройства в сети»

Приложение само ищет телевизоры по mDNS — это протокол, которым устройства
объявляют о себе в локальной сети. **Ни адрес, ни порт знать не нужно**: если
телевизор найден, он появится здесь сам.

Каждая строка показывает имя, адрес и вид устройства:

*   **«Отладка по сети»** — классическая отладка на порту 5555. Кнопка
    **«Подключиться»** работает сразу.
*   **«Готово к подключению»** — беспроводная отладка Android 11+, устройство
    объявляет TLS-порт. Это не подтверждение спаривания с вашим приложением:
    при первом подключении может потребоваться код.
*   **«Ожидает спаривания»** — на экране телевизора открыт диалог спаривания.
    Подключиться нельзя, пока не введён код, поэтому кнопка здесь —
    **«Спарить»**: она подставит адрес в форму спаривания ниже.

Если список пуст, ничего страшного: вводите адрес руками в разделе выше.

**Про запрос на экране телевизора.** При первом подключении телевизор спросит
разрешение на отладку с этого устройства и покажет **отпечаток ключа**. Это
нормальный шаг, а не сбой: так Android убеждается, что подключается именно тот,
кого вы ожидаете. Подтвердите запрос на экране ТВ; отметка «Всегда разрешать»
избавит от повторов при следующих подключениях. Пока запрос не подтверждён,
приложение будет отвечать «Подтвердите запрос на экране устройства».

**Про разрешения.** Используемый системный mDNS на Android 13-16 не требует
`NEARBY_WIFI_DEVICES`. В текущей сборке (`targetSdk = 36`) дополнительный
запрос не нужен и на Android 17. При переходе на target SDK 37 потребуется
`ACCESS_LOCAL_NETWORK`; отказ ограничит не только поиск, но и прямое
подключение по адресу. Основание: [правила доступа к локальной сети Android](https://developer.android.com/privacy-and-security/local-network-permission).

#### 4. «Спаривание устройства» — код для Android 11 и новее

Форма спаривания показывается, **когда соединения нет**. Как только вы
подключились, она исчезает — она больше не нужна. Если нужно спарить другое
устройство, нажмите «Отключиться».

Спаривание требуется только там, где в настройках разработчика есть пункт
**«Беспроводная отладка»**. Если у вас, как на Nvidia Shield, есть только
«Отладка по сети» — спаривание не нужно вовсе, подключайтесь напрямую.

Для TLS-сопряжения APK должен работать на **Android 10+**: это требование
к клиенту, а не к версии телевизора. На Android 6-9 остаётся классический
ADB. На управляемом устройстве нужна беспроводная отладка: официально для
телефонов Android 11+, для TV Android 13+, с учётом возможностей прошивки.
См. [официальную документацию ADB](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi).

**Порядок действий:**

1. На главном экране **Беспроводной отладки** запомните адрес подключения,
   например `192.168.0.112:37105`, либо найдите его через mDNS.
2. Откройте **Подключение с помощью кода**. Телевизор покажет **код из шести цифр** и строку вида
   `192.168.0.112:41234`. **Это адрес спаривания.**
3. Оставьте окно с кодом открытым до завершения сопряжения. Закрытие окна
   может остановить сервер сопряжения; не возвращайтесь назад ради второго порта.
4. В приложении заполните три поля:

| Поле | Что вводить | Пример |
|---|---|---|
| Адрес для спаривания | адрес из окна с кодом | `192.168.0.112:41234` |
| Код из 6 цифр | код с экрана телевизора | `473829` |
| Адрес для подключения | адрес с главного экрана отладки | `192.168.0.112:37105` |

5. Нажмите **«Спарить и подключиться»**.

**Главное, на чём спотыкаются все:** порт спаривания и порт подключения —
**разные**, хотя оба показаны на одном экране телевизора и оба начинаются с
одного IP. Если подставить порт спаривания в оба поля, ничего не выйдет.

**Используйте код из текущего открытого окна.** Если приложение ответило «Устройство
отвергло код спаривания», закройте окно на телевизоре, откройте заново и
возьмите свежий код: порт при этом тоже сменится.

Кнопка **«Спарить»** у найденного устройства заполняет первое поле за вас —
адрес спаривания приложение уже знает из поиска по сети.

ADB-ключ APK сохраняется в приватном каталоге без резервного копирования.
Перезапуск приложения больше не меняет ключ. После обновления со старой
версии с ключом только в памяти потребуется одно новое сопряжение.
Очистка данных/переустановка, отзыв доступа или истечение авторизации на TV
также могут потребовать новый код. Код сопряжения на диске не сохраняется.
Ожидание ограничено: TCP 10 секунд, чтение/TLS 15 секунд, вся операция
сопряжения 60 секунд. Для адресов приложения пока используется IPv4.

Описание исправлений и проверок находится в
[примечаниях к выпуску 2.6.1](release-notes/v2.6.1-ru.md).

#### 5. «Сервер времени»

Раздел появляется только после подключения.

Первая строка — **«Текущий:»** — это значение, **прочитанное с телевизора**, а
не то, что вы вводили. Когда сервер задан, строка выделена **зелёным**; «Сервер
времени не задан» значит, что на устройстве он не прописан и используется
системный по умолчанию.

Результат применения выделяется так же: **зелёным** — «Установлен сервер
времени …», **красным** — любая неудача. То же и у кнопки «Проверить»: годный
сервер зелёный, отвергнутый красный.

**Как выбрать сервер — три способа:**

*   **Поиск.** Начните печатать код страны, её название или часть адреса:
    `ru`, `by`, `kz`, `Россия`, `cloudflare`. Нажатие на найденную строку
    **подставляет адрес в поле ниже** — настройка при этом не меняется.
*   **Список стран.** Когда поиск пуст, есть кнопка **«Показать страны и их
    коды (77)»**. Коды помнить не нужно: список показывает и код, и название, и
    адрес — `RU · Россия · ru.pool.ntp.org`, `KZ · Казахстан · kz.pool.ntp.org`,
    `BY · Беларусь · by.pool.ntp.org` и так далее.
*   **Список альтернативных серверов.** Кнопка **«Показать альтернативные
    серверы времени (45)»** — тот же перечень, что и в десктопной версии:
    региональные пулы, Cloudflare, Google, российские серверы ВНИИФТРИ и другие.
*   **Вручную.** В поле «Адрес сервера времени» можно ввести и доменное имя
    (`time.google.com`), и IP-адрес (`216.239.35.0`) — под полем об этом есть
    напоминание.

**Кнопка «Проверить»** отправляет на выбранный адрес настоящий запрос по
протоколу NTP и разбирает ответ. Ответ должен быть именно ответом сервера
времени и содержать время, близкое к настоящему. Возможные исходы:

*   *«Отвечает как сервер времени: 42 мс, ответов 100 %, расхождение часов
    +0,3 с»* — годен.
*   *«Не отвечает как сервер времени: …»* — по адресу либо никого нет, либо там
    не сервер времени.
*   *«Отвечает, но сообщает сильно неверное время»* — такой сервер сломает
    часы, а не починит.

**Кнопка «Применить»** делает то же самое и, если проверка пройдена,
записывает адрес на телевизор. Результат появляется **прямо под кнопкой**, а
строка «Текущий:» обновляется значением, **перечитанным с устройства**.

*   *«Установлен сервер времени …»* — готово.
*   *«Устройство по-прежнему сообщает …»* — команда прошла, но запись не
    состоялась. Обычно это значит, что у подключения нет прав менять защищённые
    настройки.
*   *«Не применено: …»* — адрес не прошёл проверку. Рядом появится кнопка
    **«Применить всё-таки»**: проверка идёт из сети телефона, а UDP-порт 123
    закрывают некоторые операторы и роутеры, и запрещать наглухо было бы
    неправильно.

**Кнопка «Подобрать лучший»** проверяет все 122 известных адреса и показывает
пятёрку с наименьшим временем отклика. Идёт около полуминуты, показывает
«Проверено N из 122, годных M» и останавливается кнопкой **«Остановить»** —
найденное при этом сохраняется.

У каждого найденного сервера показываются **две строки**: имя и его IP-адрес.
Нажатие на имя подставляет в поле имя, нажатие на IP — числовой адрес.
Это не прихоть: часть прошивок телевизоров не умеет разрешать доменные имена,
и тогда сервер нужно задавать именно числом. Дополнительного запроса к DNS для
этого не делается — адрес уже известен от самой проверки. Применить выбранное
нужно отдельно, кнопкой «Применить».

#### 6. «Устройство»

Сведения, прочитанные с телевизора: модель, производитель, версия Android и
уровень API, серийный номер, процессор и число ядер, память, разрешение и
плотность экрана, часовой пояс, локаль, батарея, версия ядра, время работы и
текущий сервер времени. Кнопка **«Обновить»** перечитывает всё заново.

Пустые строки не показываются: если прошивка не отвечает на какую-то команду,
пропадёт только соответствующая строка, а не весь раздел.

### Если приложение ведёт себя странно

При аварийном закрытии приложение сохраняет причину и показывает её **при
следующем запуске** карточкой вверху экрана. Этот текст стоит приложить к
сообщению об ошибке — по нему причина видна сразу.

### Чего приложение не умеет

В отличие от десктопной версии, здесь нет: сканирования всей подсети,
группового обновления нескольких телевизоров, режима терминала, избранных
серверов и экспорта настроек. Для этого пользуйтесь программой для компьютера.

### Режим телевизора

APK на самом Android TV предлагает подключение к `127.0.0.1:5555` для
классической отладки. Возможность такого соединения зависит от прошивки.
Для беспроводной отладки используйте сопряжение и актуальный TLS-порт.


## Совместимость

Программа протестирована и должна работать на устройствах Android TV (включая Nvidia Shield), которые соответствуют следующим требованиям:

*   Поддержка ADB по сети — в любом из двух вариантов: классическая
    «Отладка по сети» (порт 5555) или «Беспроводная отладка» Android 11+
    со спариванием по коду.
*   Поддержка управления NTP-сервером через команды `adb shell`.

Проверено на устройствах с Android от 9 до 16. На Google TV Streamer и
Chromecast with Google TV после обновления до Android 14 доступна только
беспроводная отладка — используйте пункт 11 меню.

**Поддерживаемые операционные системы:**
*   Windows 10/11
*   Linux (Ubuntu, Debian, Fedora и др.)
*   macOS

**Приложение для Android:** Android 6.0 и новее для legacy ADB; TLS-сопряжение
требует Android 10+ на устройстве с APK и поддержки Wireless debugging на
управляемом устройстве (телефон Android 11+, TV Android 13+).
