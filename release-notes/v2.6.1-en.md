# v2.6.1 Pre-release: Wireless Debugging Fixes for Android and Desktop

**The Android app operates in test mode.**

This update fixes wireless ADB integration following a review of official
Android documentation, Android 14 AOSP source and the published Kadb artifacts.
It focuses on code pairing, reconnecting, bounded network operations and
device discovery on Android 14+.

## Android APK Fixes

- **Persistent ADB identity.** The key is written atomically to private,
  non-backed-up app storage. Process termination, restarting and Activity
  recreation no longer create a new identity. A damaged existing key is
  not silently replaced.
- **Bounded pairing.** TCP connection timeout is 10 seconds, TLS/read timeout
  is 15 seconds and the overall pairing deadline is 60 seconds. Cancelling
  the operation closes the actual socket to interrupt blocked I/O.
- **UI recovery.** Busy state is cleared in `finally`, including coroutine
  cancellation, so a stalled pairing operation cannot leave actions disabled
  indefinitely.
- **Actionable errors.** Authentication rejection, timeout, TLS failure,
  interrupted/invalid protocol exchange and network unreachability have
  separate Russian and English messages. A peer closing the exchange is not
  incorrectly treated as proof of a wrong code.
- **Android 14+ mDNS lifecycle.** Continuous NSD subscriptions no longer wait
  for a guaranteed first update. An expired pairing service cannot block a
  connect service. Callbacks from previous discovery sessions are ignored,
  subscriptions are removed when services disappear or discovery stops, and
  duplicate announcements are deduplicated. Older APIs retain serialized
  resolution with state reset on stop/start.
- **No unnecessary nearby-Wi-Fi prompt.** The NSD APIs used here do not require
  `NEARBY_WIFI_DEVICES`. Android 17 LAN permission handling now considers both
  the OS and target SDK. The current target SDK remains 36.
- **Explicit client compatibility.** TLS pairing is disabled with an
  explanation on Android 6-9. The APK still supports Android 6+ for legacy ADB;
  TLS pairing requires Android 10+ on the device running the app.
- **Usable discovered addresses.** IPv6-only endpoints are no longer offered
  to the current IPv4-only address parser. Full IPv6 support is not introduced.

## Desktop Fixes

- An `adb connect` response such as `failed to authenticate to ...` is no
  longer accepted as success, even when adb exits with code 0.
- A connection is confirmed only after a positive response for the selected
  endpoint and a short real shell probe. A failed probe closes the transport
  before the application publishes a connected state.
- Both new and existing successful connections are supported, including adb
  daemon startup messages preceding the connection response.
- Existing desktop mDNS mechanisms and the legacy/TLS transport separation
  have not been replaced.

## Signing Data Protection

The APK signing key and passwords remain in GitHub Actions Secrets. The
temporary keystore is created with private permissions and removed by an
`always()` cleanup step. Gradle configuration caching is disabled for signed
release builds. `.gitignore` now covers additional key/keystore
formats and local signing configuration files. Secret values are not included
in source code or release notes.

## Upgrade Notes

1. Pair once more after upgrading from the old APK: it kept its key only in
   process memory and could not restore it after process termination.
2. Note the connection address on the main wireless-debugging screen before
   opening the code dialog. Keep that dialog open until pairing completes.
   Pairing and connection ports are different and can change.
3. A discovered service labelled "Ready to connect" advertises a TLS endpoint;
   it does not prove that the TV trusts this client. First-time access may
   still require code pairing.
4. Clearing app data, reinstalling, revoked trust or expired TV authorization
   can require pairing again even with persistent app identity.

## Validation And Limitations

Regression coverage includes persisted identity, real TLS 1.3, SPAKE2,
AES-GCM PeerInfo, CNXN/STLS/shell, incorrect codes/tags, malformed packets,
timeouts, cancellation and NSD callback ordering. A separate localhost test
uses the actual platform-tools adb binary to verify zero-exit authentication
failure handling. Android CI uses JDK 21 to execute the published Kadb AAR
classes; the app's Java target remains 17. Test-only Conscrypt is not packaged
into the APK.

**No physical Android TV 14 device was tested.** Protocol fixtures cannot
validate device-specific system Conscrypt/hidden API access, UI or OEM
firmware behavior. The controlled device must offer wireless debugging:
officially Android 11+ phones and Android 13+ TVs, depending on firmware
availability. An IPv4 network and distinct, current pairing/connection ports
are still required.

Official sources: [ADB documentation](https://developer.android.com/tools/adb)
and the [Android 14 ADB source code](https://android.googlesource.com/platform/packages/modules/adb/+/android-14.0.0_r1/).
