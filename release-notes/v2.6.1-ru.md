# v2.6.1 Pre-release: беспроводная отладка Android APK и desktop

**Приложение для Android работает в тестовом режиме.**

Обновление исправляет интеграцию беспроводного ADB после сопоставления с
официальной документацией Android, исходниками AOSP 14 и опубликованным Kadb.
Основное внимание уделено сопряжению по коду, повторному подключению,
ограничению ожидания и обнаружению устройств на Android 14+.

## Исправления Android APK

- **Постоянный ADB-ключ.** Ключ сохраняется атомарно в приватном каталоге
  приложения, исключённом из резервного копирования. Завершение процесса,
  повторный запуск или пересоздание Activity больше не создают новую
  идентичность. Повреждённый существующий ключ не заменяется молча.
- **Ограниченное ожидание сопряжения.** Добавлены таймауты TCP-подключения
  10 секунд, TLS/чтения 15 секунд и общий лимит pairing 60 секунд.
  Отмена операции закрывает настоящий сокет, прерывая заблокированный обмен.
- **Восстановление интерфейса.** Состояние занятости сбрасывается в `finally`,
  включая отмену coroutine; pairing не должен навсегда блокировать действия.
- **Понятные причины отказа.** Различаются ошибка аутентификации, таймаут,
  ошибка TLS, прерванный/неверный обмен и недоступность адреса. Сообщения
  добавлены на русском и английском. Разрыв peer не объявляется достоверным
  доказательством неверного кода.
- **mDNS на Android 14+.** Непрерывные NSD-подписки больше не ожидают
  обязательного первого update. Исчезнувшее окно pairing не блокирует
  обнаружение connect-сервиса; поздние callbacks прошлой сессии игнорируются.
  Подписки снимаются при потере сервиса и остановке поиска, повторные
  объявления дедуплицируются. Для старых API сохранён последовательный resolve
  со сбросом состояния при stop/start.
- **Разрешения без лишнего запроса.** Удалён ненужный `NEARBY_WIFI_DEVICES`
  для используемого NSD. Правило LAN permission на Android 17 учитывает
  одновременно версию ОС и target SDK; текущий target 36 сохранён.
- **Явная совместимость клиента.** На Android 6-9 кнопка TLS-сопряжения
  отключена с пояснением. APK по-прежнему устанавливается начиная с Android 6
  и поддерживает legacy ADB; pairing требует Android 10+ на клиенте.
- **Корректные адреса.** NSD не предлагает IPv6-only адреса, не поддержанные
  текущим вводом/валидатором приложения. Полноценная IPv6-поддержка не добавлена.

## Исправления Desktop

- Ответ `adb connect` вида `failed to authenticate to ...` больше не
  принимается за успех, даже когда adb возвращает exit code 0.
- Подключение подтверждается положительным ответом для выбранного адреса
  и короткой реальной shell-командой. При провале shell-пробы транспорт
  закрывается до публикации состояния «Подключено».
- Сохранены оба корректных ответа adb: новое и уже существующее подключение,
  в том числе с сообщениями запуска ADB-сервера перед основным ответом.
- Рабочие механизмы desktop mDNS и разделение legacy/TLS не заменялись.

## Защита Данных Подписи

Ключ подписи APK и пароли остаются в GitHub Actions Secrets. Временное
хранилище ключа создаётся с закрытыми правами и удаляется отдельным шагом
`always()`. Для сборки с подписью отключён Gradle configuration cache.
В `.gitignore` добавлены форматы ключей/хранилищ и локальные
файлы настроек подписи. Значения секретов не входят в код или описания релиза.

## Перед Обновлением

1. После перехода со старого APK потребуется один раз повторить сопряжение:
   прежняя версия держала ключ только в памяти и не могла восстановить его
   после завершения процесса.
2. Сначала узнайте connect-адрес на главном экране беспроводной отладки,
   затем откройте окно с кодом. Не закрывайте его до завершения pairing.
   Порт из окна с кодом и порт подключения различаются и могут меняться.
3. Объявление mDNS «Готово к подключению» означает наличие TLS-порта,
   а не наличие доверия к вашему клиенту. При первом подключении нужен код.
4. Очистка данных, переустановка, отзыв доверия и истечение авторизации на TV
   могут потребовать новое сопряжение даже при постоянном ключе приложения.

## Проверка И Ограничения

Добавлены регрессионные проверки сохранения идентичности, настоящего TLS 1.3,
SPAKE2, AES-GCM PeerInfo, CNXN/STLS/shell, неверного кода/тега, повреждённых
пакетов, таймаутов, отмены и порядка NSD callbacks. Отдельный localhost-тест
использует настоящий platform-tools adb для проверки ложного exit-code успеха.
Android CI использует JDK 21, необходимую для выполнения классов опубликованного
Kadb AAR; Java target приложения остаётся 17. Тестовый Conscrypt в APK не входит.

**Физический Android TV 14 не тестировался.** Протокольный стенд не заменяет
проверку системного Conscrypt/hidden API, интерфейса и OEM-прошивки на устройстве.
Wireless debugging нужен на управляемом устройстве: официально Android 11+
для телефонов и Android 13+ для TV, с учётом доступности функции в прошивке.
IPv4-сеть и разные актуальные порты pairing/connect по-прежнему обязательны.

Официальные источники: [документация ADB](https://developer.android.com/tools/adb)
и [исходный код ADB в Android 14](https://android.googlesource.com/platform/packages/modules/adb/+/android-14.0.0_r1/).
