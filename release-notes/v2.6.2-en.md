# English — v2.6.2: USB connections and interface improvements

**Prerelease. The Android app operates in test mode.**

Changes since 2.6.1: ADB over USB, clearer device connection steps, local
diagnostics and Android usability improvements.

## Added

- **ADB over USB on Android, Windows, Linux and macOS.** Select a connected
  TV, set-top box, phone or tablet to configure NTP and read device information
  without entering an IP address. Wireless connection methods remain available.
- **Visible application version** in the Android app and the desktop main
  menu; `--version` is also available on the command line.
- **Android diagnostics through a separate button.** The log records results
  of USB, network connection and NTP operations. It supports copying and
  clearing with confirmation. The latest 200 events are retained for up to
  7 days, only on the device, with no automatic upload. ADB keys, passwords
  and pairing codes are not logged.
- **Clearer network discovery.** Discovered devices have a green
  “Device found” label with their name and address. Device discovery and a
  successful connection are shown as separate states.
- The pairing section explains that the code is used for the newer
  Android 11+ wireless debugging mode when the controlled device's firmware
  offers that feature.

## Fixed and improved

- The desktop USB menu explicitly asks you to enter a device number and
  press Enter. Once the connection is verified, it displays the connected
  device's name and the next steps: option 5 for information, options 1 and 2
  for NTP settings.
- The `UNAUTHORIZED` state includes instructions to approve the RSA prompt
  on the target device. A successful connection requires an ADB probe command,
  not just a device appearing in the list.
- Automatic NTP setup uses the selected USB connection.
- Android USB discovery distinguishes no devices, a USB device without an
  ADB interface, and enumeration errors. An empty list is no longer described
  as successful discovery. Diagnostics include device counts and system USB
  state information.
- Completing a long operation no longer overwrites a fresh USB device list
  with stale state. USB attachment, removal and operation cancellation are
  handled.
- A more compact Android main screen provides NTP settings after connection
  and collapsible additional sections. Input and section state are preserved
  while viewing diagnostics.
- Improved green status contrast, status bar icon visibility on light
  backgrounds, remote-control navigation, large-font layouts and landscape
  display. Buttons remain accessible with the keyboard open on older Android
  versions.
- GitHub Actions check names now show only the OS and Python version.
  Added UI checks on Android 6 and Android 16, plus a Windows build artifact
  for the `dev` branch.

## USB setup and known limitation

Enable USB debugging on the target device, use a data-capable cable and
approve the RSA prompt. A phone running the app must support USB host/OTG;
the target must use a port that supports USB device mode. Windows may require
the manufacturer's ADB driver; Linux may require udev rules.

**A Windows → NVIDIA SHIELD USB connection and reading device information
have been confirmed in user testing. Phone → SHIELD discovery remains under
investigation:** Android returns an empty USB device list on the mobile
devices tested. Version 2.6.2 improves diagnostics and state handling, but a
fix for this specific case has not yet been confirmed.
