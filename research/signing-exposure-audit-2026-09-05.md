# Проверка возможной утечки данных подписи APK

Дата: 2026-09-05, перед выпуском `v2.6.1`.

## Результат

**В проверенных источниках признаки утечки ключа или пароля подписи не
обнаружены.** Это результат ограниченного поиска признаков, а не доказательство,
что утечки никогда не было. Производственный keystore и значения паролей не
читались и не выводились. GitHub Secrets проверялись только по именам.

## Область Проверки

- Получены доступные ветки и теги GitHub-репозитория. Проверены 262 коммита,
  достижимые Git-объекты, reflog и подготовленный индекс: 471 уникальный blob
  на момент первоначального сканирования.
- В содержимом искались признаки PEM private key, JKS, PKCS12, их длинных
  base64-представлений, а также литеральные присваивания паролей подписи и
  пароли в аргументах `keytool`/`apksigner`. Совпавшие значения не печатались.
- Проверены оба завершённых запуска release workflow, доступные среди трёх
  запусков, возвращённых API репозитория. Оба архива журналов доступны;
  недоступных архивов среди выбранных запусков не было.
- Проверены имена 24 файлов существующих GitHub Releases: подозрительные
  keystore/private-key вложения не найдены. Содержимое всех release-архивов
  отдельно не распаковывалось и полностью не сканировалось.
- В доступной локальной истории найдено и просканировано 6 Codex-сессий с
  рабочим каталогом этого проекта: текст сообщений, аргументы tool calls и
  сохранённые результаты выполнения. Данные других проектов не проверялись.
- Проверена текущая конфигурация подписи: ключ приходит через GitHub Secrets
  во временный каталог runner, пароли передаются через окружение, артефакты
  публикуются по явному списку. Содержимое ключа не выводится в stdout.

## Ограничения

Без чтения фактических секретов невозможно сравнить с ними каждый произвольный
фрагмент текста. Пароль без характерной подписи/контекста может не распознаться.
Маскирование GitHub также не позволяет восстановить прошлые значения.
Удалённые/недоступные логи, недостижимая удалённая история, другие чаты и
внешние копии не охвачены. Публичный сертификат подписи в APK сам по себе не
является утечкой приватного ключа.

Если известно конкретное сообщение или файл, где публиковались реальные
данные подписи, отсутствие находок здесь не отменяет необходимость отдельной
оценки компрометации. Такой материал нельзя повторно вставлять в общий чат.

## Усиление Защиты

- Перед декодированием keystore в workflow установлен `umask 077`.
- Добавлено удаление временного keystore отдельным шагом с `if: always()`.
- Для подписываемой release-сборки отключён Gradle configuration cache,
  чтобы конфигурация с паролями не сериализовалась в этот кэш.
- В `.gitignore` добавлены дополнительные форматы ключей/хранилищ, локальные
  signing properties и environment-файлы.
- В постоянной памяти сохранены запрет публикации данных подписи и правило
  использовать только `civisrom <civisrom@users.noreply.github.com>` для
  запрошенных коммитов этого проекта; реальные email не используются.
- В Git и описания релиза включены только ссылки на имена Secrets, не значения.
